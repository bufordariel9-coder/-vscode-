# 矩阵按键实现方案与验证方案

## 1. 目标

实现 18 个矩阵按键扫描，矩阵规模为 6 行 4 列。

按键按下时，通过 RTT 打印逻辑坐标：

- 第一行第一列打印为 `[0,0]`
- 第二行第一列打印为 `[1,0]`
- 坐标使用 0 起始编号
- 只打印有效按键位置

本阶段只实现矩阵按键坐标输出，不做 USB HID、BLE HID、2.4G 上报。

## 2. 采用 Zephyr/NCS 现成模块

已在 NCS v3.2.3 / Zephyr 中找到官方输入模块：

- 驱动：`gpio-kbd-matrix`
- 源码：`D:\ncs\v3.2.3\zephyr\drivers\input\input_gpio_kbd_matrix.c`
- 公共矩阵扫描：`D:\ncs\v3.2.3\zephyr\drivers\input\input_kbd_matrix.c`
- Devicetree binding：`D:\ncs\v3.2.3\zephyr\dts\bindings\input\gpio-kbd-matrix.yaml`
- 输入事件接口：`D:\ncs\v3.2.3\zephyr\include\zephyr\input\input.h`

因此本项目不手写矩阵扫描和消抖逻辑，直接使用 Zephyr 提供的 `gpio-kbd-matrix` 驱动。

驱动会输出三类 input 事件：

```text
INPUT_ABS_X     当前物理列 col
INPUT_ABS_Y     当前物理行 row
INPUT_BTN_TOUCH 按下/释放状态
```

应用层注册 `INPUT_CALLBACK_DEFINE()` 回调，记录最近一次 X/Y，在 `INPUT_BTN_TOUCH == 1` 时将物理坐标转换为逻辑坐标，并通过 RTT 打印。

## 4. 物理按键分布

原理图物理矩阵共 18 个有效按键：

| 物理行 | 有效物理列 | 按键数量 |
| --- | --- | --- |
| ROW0 | COL3 | 1 |
| ROW1 | COL0, COL1, COL2, COL3 | 4 |
| ROW2 | COL0, COL1, COL2 | 3 |
| ROW3 | COL0, COL1, COL2, COL3 | 4 |
| ROW4 | COL0, COL1, COL2 | 3 |
| ROW5 | COL0, COL1, COL3 | 3 |

`gpio-kbd-matrix` 的 `actual-key-mask` 按物理列配置：

| 物理列 | 有效行 bit | 掩码 |
| --- | --- | --- |
| COL0 | ROW1~ROW5 | `0x3e` |
| COL1 | ROW1~ROW5 | `0x3e` |
| COL2 | ROW1~ROW4 | `0x1e` |
| COL3 | ROW0, ROW1, ROW3, ROW5 | `0x2b` |

## 5. 逻辑坐标映射

用户期望按键按布局顺序输出坐标，而不是完全照原理图物理列输出。

因此应用层增加物理坐标到逻辑坐标的映射表：

| 物理坐标 | 逻辑坐标 |
| --- | --- |
| `[0,3]` | `[0,0]` |
| `[1,0]` | `[1,0]` |
| `[1,1]` | `[1,1]` |
| `[1,2]` | `[1,2]` |
| `[1,3]` | `[1,3]` |
| `[2,0]` | `[2,0]` |
| `[2,1]` | `[2,1]` |
| `[2,2]` | `[2,2]` |
| `[3,0]` | `[3,0]` |
| `[3,1]` | `[3,1]` |
| `[3,2]` | `[3,2]` |
| `[3,3]` | `[3,3]` |
| `[4,0]` | `[4,0]` |
| `[4,1]` | `[4,1]` |
| `[4,2]` | `[4,2]` |
| `[5,0]` | `[5,0]` |
| `[5,1]` | `[5,1]` |
| `[5,3]` | `[5,2]` |

这样可以满足：

- 第 1 行只有 1 个按键，但输出为 `[0,0]`
- 第 6 行物理上使用 `COL3` 的第三个按键，输出为 `[5,2]`

## 6. Devicetree 实现方案

GPIO 设置集中在 `boards/mini_keybrad/mini_keybrad/mini_keybrad.dts` 中：

```dts
/ {
    kbd_matrix: kbd-matrix {
        compatible = "gpio-kbd-matrix";

        row-gpios = <&gpio0 15 (GPIO_PULL_UP | GPIO_ACTIVE_LOW)>,
                    <&gpio0 7  (GPIO_PULL_UP | GPIO_ACTIVE_LOW)>,
                    <&gpio0 12 (GPIO_PULL_UP | GPIO_ACTIVE_LOW)>,
                    <&gpio0 4  (GPIO_PULL_UP | GPIO_ACTIVE_LOW)>,
                    <&gpio1 9  (GPIO_PULL_UP | GPIO_ACTIVE_LOW)>,
                    <&gpio0 8  (GPIO_PULL_UP | GPIO_ACTIVE_LOW)>;

        col-gpios = <&gpio0 5  GPIO_ACTIVE_LOW>,
                    <&gpio0 6  GPIO_ACTIVE_LOW>,
                    <&gpio0 26 GPIO_ACTIVE_LOW>,
                    <&gpio0 30 GPIO_ACTIVE_LOW>;

        actual-key-mask = <0x3e 0x3e 0x1e 0x2b>;
        no-ghostkey-check;
        col-drive-inactive;
        idle-mode = "scan";
        poll-timeout-ms = <0>;
        poll-period-ms = <5>;
        debounce-down-ms = <10>;
        debounce-up-ms = <20>;
        settle-time-us = <50>;
    };
};
```

说明：

- `row-gpios` 顺序就是物理 `ROW0~ROW5`。
- `col-gpios` 顺序就是物理 `COL0~COL3`。
- `GPIO_PULL_UP | GPIO_ACTIVE_LOW` 表示行输入上拉，按下为低有效。
- `GPIO_ACTIVE_LOW` 表示列被选中时输出低电平。
- `idle-mode = "scan"` 让矩阵持续扫描，方便本阶段调试。
- `no-ghostkey-check` 适用于带二极管矩阵。

## 8. main.c 实现方案

应用层逻辑：

1. 注册 input callback。
2. 收到 `INPUT_ABS_X` 时记录物理列。
3. 收到 `INPUT_ABS_Y` 时记录物理行。
4. 收到 `INPUT_BTN_TOUCH` 且 value 为 1 时，认为按键按下。
5. 查询物理坐标到逻辑坐标映射表。
6. 找到有效按键则 RTT 打印：`key down [row,col]`。
7. 释放事件可选择打印或暂不打印，第一阶段建议也打印，便于验证消抖。

伪代码：

```c
static int current_phys_row = -1;
static int current_phys_col = -1;

static void input_cb(struct input_event *evt, void *user_data)
{
    if (evt->type == INPUT_EV_ABS && evt->code == INPUT_ABS_X) {
        current_phys_col = evt->value;
    } else if (evt->type == INPUT_EV_ABS && evt->code == INPUT_ABS_Y) {
        current_phys_row = evt->value;
    } else if (evt->type == INPUT_EV_KEY && evt->code == INPUT_BTN_TOUCH) {
        if (evt->value == 1) {
            print_logical_coordinate(current_phys_row, current_phys_col);
        }
    }
}

INPUT_CALLBACK_DEFINE(NULL, input_cb, NULL);
```

## 9. 验证方案

### 9.1 编译验证

使用当前 NCS/Zephyr 环境编译：

```powershell
cmake --build build_test
```

如果还没有 build 目录，则先配置：

```powershell
west build -b nrf52840dk/nrf52840 -d build_test .
```

验证点：

- 编译无 Devicetree 错误。
- `CONFIG_INPUT_GPIO_KBD_MATRIX` 被自动选中。
- `app.overlay` 被正确合入。

### 9.2 RTT 输出验证

烧录后打开 RTT Viewer 或 J-Link RTT Client。

逐个按键测试，期望输出：

| 布局按键 | 期望 RTT 输出 |
| --- | --- |
| 第 1 行第 1 个 | `key down [0,0]` |
| 第 2 行第 1 个 | `key down [1,0]` |
| 第 2 行第 4 个 | `key down [1,3]` |
| 第 3 行第 3 个 | `key down [2,2]` |
| 第 4 行第 4 个 | `key down [3,3]` |
| 第 5 行第 3 个 | `key down [4,2]` |
| 第 6 行第 3 个 | `key down [5,2]` |

### 9.3 行列方向验证

如果所有按键都没有输出：

1. 检查 `row-gpios` 和 `col-gpios` 是否反了。
2. 检查是否需要把行列电平从 `GPIO_ACTIVE_LOW` 改为 `GPIO_ACTIVE_HIGH`。
3. 检查二极管方向是否与当前“列输出低、行输入上拉”的扫描方式一致。

如果部分按键坐标错乱：

1. 只修改 `boards/mini_keybrad/mini_keybrad/mini_keybrad.dts` 中 `row-gpios` 或 `col-gpios` 的顺序。
2. 如果只是布局坐标不符合预期，只修改 `main.c` 中的物理到逻辑坐标映射表。

### 9.4 消抖验证

连续快速点击同一个按键：

- 正常情况：每次按下只出现一次 `key down`。
- 如果一次按下出现多次输出，增加 `debounce-down-ms`。
- 如果释放后再次按下反应慢，适当降低 `debounce-up-ms`。

### 9.5 多键验证

同时按下同一行或同一列多个键：

- 因为硬件带二极管，启用 `no-ghostkey-check`。
- 验证多个键是否都能正常输出。
- 若多键异常，复查二极管方向和 `actual-key-mask`。
