# 蓝牙小键盘总体规划

## 1. 项目目标

基于当前 Zephyr/NCS 工程和硬件原理图，实现一个支持三模连接的小键盘固件：

- USB HID：第一阶段优先实现，作为主要调试和有线键盘模式。
- BLE HID：第二阶段实现，作为无线蓝牙键盘模式。
- 2.4G：暂不实现具体通信协议，仅预留架构和模式入口。

整体目标是让按键矩阵、旋钮、RGB、电池、电源和后续屏幕显示都围绕统一输入事件和统一 HID 报告层开发，避免不同连接模式重复实现业务逻辑。

| 电池 ADC | BAT_ADC | U36.9 |

## 4. 软件总体架构

核心原则：输入层只产生统一事件，不直接关心当前连接模式。

```text
按键矩阵 / EC11 旋钮
        ↓
input_event 输入事件层
        ↓
keymap / layer 键位映射层
        ↓
hid_report HID 报告生成层
        ↓
transport_manager 连接管理层
        ↓
USB HID / BLE HID / 2.4G 占位
```

建议目录结构：

```text
src/
  main.c
  matrix.c
  matrix.h
  encoder.c
  encoder.h
  keymap.c
  keymap.h
  hid_report.c
  hid_report.h
  transport.h
  transport_usb.c
  transport_ble.c
  transport_24g.c
  mode_manager.c
  rgb.c
  rgb.h
  battery.c
  battery.h
  power.c
  power.h
```

## 5. 三模连接方案

| 模式 | 实现阶段 | 说明 |
| --- | --- | --- |
| USB HID | 第一阶段 | 插 USB 后作为标准键盘/媒体键设备 |
| BLE HID | 第二阶段 | 蓝牙键盘，支持配对、回连、电池服务 |
| 2.4G | 预留 | 暂不实现协议，仅保留接口和模式入口 |

推荐连接优先级：

1. 检测到 VBUS 时，优先使用 USB HID。
2. 无 USB 时，默认使用 BLE HID。
3. 2.4G 模式可以通过按键切换进入，但当前仅提示未实现或保持空闲。

后续可扩展为：

- USB：有线键盘模式。
- BLE1 / BLE2 / BLE3：多蓝牙设备切换。
- 2.4G：私有接收器模式。

## 6. Transport 抽象

预留统一传输接口，USB、BLE、2.4G 都实现同一组函数。

```c
struct hid_transport {
    int (*init)(void);
    int (*connect)(void);
    int (*disconnect)(void);
    int (*send_keyboard)(const struct hid_keyboard_report *report);
    int (*send_consumer)(uint16_t usage);
    bool (*is_ready)(void);
};
```

2.4G 暂时实现为空模块：

- 初始化成功或返回明确状态。
- 发送接口返回 `-ENOTSUP`。
- 模式切换时系统不崩溃。
- 后续确定 2.4G 芯片、接收器和协议后再补全。

## 7. USB HID 阶段规划

目标：电脑通过 USB 识别为标准 HID 键盘。

实现内容：

- 启用 Zephyr USB device stack。
- 实现 HID keyboard report。
- 实现 consumer/media report。
- 矩阵扫描后发送 USB HID 按键报告。
- EC11 旋钮默认映射为音量加减。
- EC11 按下默认映射为静音或播放/暂停。
- 使用串口日志辅助确认按键位置和报告内容。

初步配置方向：

```conf
CONFIG_GPIO=y
CONFIG_LOG=y
CONFIG_USB_DEVICE_STACK=y
CONFIG_USB_DEVICE_HID=y
CONFIG_HID=y
```

## 8. BLE HID 阶段规划

目标：断开 USB 后作为 BLE 键盘使用。

实现内容：

- 启用 BLE peripheral。
- 实现 HID over GATT。
- 添加 Battery Service。
- 支持配对、绑定保存、自动回连。
- 同一份 HID report 可发送到 BLE transport。
- 支持 Fn 组合键进入配对和清除绑定。

初步配置方向：

```conf
CONFIG_BT=y
CONFIG_BT_PERIPHERAL=y
CONFIG_BT_HIDS=y
CONFIG_BT_BAS=y
CONFIG_SETTINGS=y
CONFIG_BT_SETTINGS=y
```

## 9. RGB 规划

硬件为 WS2812B-MINI 链式 RGB，数据入口为 `RGB_DATA`，电源由 `RGB_PWR_EN` 控制。

实现内容：

- 上电默认关闭或低亮度。
- USB 模式允许较高亮度。
- BLE 模式默认降低亮度以省电。
- 支持常亮、呼吸、按键响应、关闭。
- 低电量时自动降低亮度或关闭。

优先使用 Zephyr `led_strip` 或适合 nRF52 的定时/PWM/SPI 方式输出 WS2812 时序。

## 10. 电池与电源规划

电池检测：

- 使用 `BAT_ADC_EN` 打开分压。
- 延时稳定后读取 `BAT_ADC`。
- 读取完成关闭 `BAT_ADC_EN`，降低静态功耗。
- 周期建议 30s 到 60s。

电源管理：

- USB 插入时检测 `VBUS` 并切换到 USB HID。
- BLE 空闲后降低扫描频率或进入低功耗。
- RGB 和屏幕作为主要耗电模块，需要支持自动关闭。
- IP5305T 通过 I2C 做充电/电源状态管理，第二阶段后再完善。

## 11. 屏幕规划

屏幕接口存在 `SCREEN_BLK`、`SCREEN_CS`、`SCREEN_DC`、`SCREEN_RES`、`SCREEN_SCL`、`SCREEN_SDA`，优先作为后置功能。

实现顺序：

1. 确认屏幕驱动芯片型号。
2. 点亮背光和复位。
3. 通过 SPI 或兼容接口初始化屏幕。
4. 显示连接模式、电池电量、当前层、RGB 模式。

## 12. 模式切换建议

默认行为：

- 插入 USB：优先 USB HID。
- 未插 USB：默认 BLE HID。
- 2.4G：通过组合键进入预留模式。

建议组合键：

| 操作 | 功能 |
| --- | --- |
| Fn + 1 | USB 模式 |
| Fn + 2 | BLE 模式 |
| Fn + 3 | 2.4G 模式，当前占位 |
| Fn + Esc | 清除 BLE 绑定 |
| Fn + RGB | 切换灯效 |

第一版建议采用“USB 插入自动优先”，符合普通用户直觉，也便于开发调试。

## 13. 开发路线

第一阶段：USB HID 基础可用

1. 建立 board 或 devicetree overlay。
2. 配置矩阵 GPIO、EC11 GPIO、LED GPIO、VBUS 检测。
3. 点亮 LED，验证 GPIO。
4. 实现矩阵扫描和串口打印。
5. 实现 EC11 旋钮识别。
6. 接入 USB HID，电脑识别为键盘。
7. 实现基础 keymap 和媒体键。

第二阶段：三模框架和 BLE

1. 添加 `transport_manager`。
2. 添加 `transport_usb.c`。
3. 添加 `transport_ble.c`。
4. 添加 `transport_24g.c` 占位。
5. 实现 BLE HID 配对、回连和电池服务。
6. 实现模式切换逻辑。

第三阶段：体验增强

1. RGB 电源控制和基础灯效。
2. 电池 ADC 和低电量策略。
3. IP5305T 电源状态读取。
4. 配置保存。
5. 低功耗优化。

第四阶段：产品化

1. 屏幕显示。
2. USB/BLE 模式稳定性测试。
3. 出厂测试模式。
4. OTA/DFU。
5. 后续补充 2.4G 协议实现。

## 14. 当前最优先任务

当前工程是 Zephyr/NCS 空工程，优先任务不是直接写复杂业务，而是先跑通硬件基础链路：

1. 确认 E73-2G4M08S1C 对应的具体芯片和 Zephyr board target。
2. 编写 devicetree overlay 或自定义 board。
3. 实现 GPIO LED 测试。
4. 实现矩阵扫描串口输出。
5. 实现 USB HID 键盘输出。

完成以上内容后，再进入 BLE HID 和三模连接管理。
